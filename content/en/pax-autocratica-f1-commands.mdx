## A safe command test routine

The safest routine is controlled and reversible. Start from a low-stakes encounter, issue one order, wait long enough to observe troop spacing, then issue the next order. Do not stack multiple command changes while the squad is already under heavy fire, because you will not know which input caused the behavior change.

If you are trying to keep troops alive, compare the result against your current goal: close formation can keep soldiers near you but may expose them to area damage, while wider spacing or a hold-style order may reduce clustering but can leave slower soldiers isolated. The current public sources do not verify exact numerical distances, so the page avoids inventing them.

1. Save before the expedition if the run matters.
2. Enter a low-risk battle with expendable or non-critical troops.
3. Press the current command input shown by the game and observe one behavior change at a time.
4. Write down the visible order label, troop spacing and whether target selection changes.
5. Only reuse the command in harder fights after it behaves consistently in your current build.

## What not to infer from old videos

YouTube reviews and long-form play videos are helpful for seeing how the colony and FPS halves connect, but they are not always current control documentation. Unless a video shows the exact current build and the visible command prompt, use it as a discovery source rather than proof.

This matters because the official Frontline post says combat controls are still under active polish. A command that looked awkward in one video may have changed, and a command that looked clear in one session may not be enough to explain another player's build.

1. Use videos to discover what to test, not to replace the current in-game control prompt.
2. Avoid copying a command sequence from a video unless the build date is clear.
3. When reporting command issues, include the order label, battle type, troop count and build date.
