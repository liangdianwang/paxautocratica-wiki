## Practical save routine before an expedition

The practical routine is conservative because it protects progress without claiming more than the sources prove. Make a stable base-side save before launching an expedition. During map flight, use the manual save action only when the current UI allows it and wait for a visible save confirmation. During active combat, assume the restore point may be constrained by the current build until you have personally tested it.

If the next load sends you back to base, do not immediately overwrite the evidence. Keep the last known good save if possible, note the exact phase where you saved, and compare it with AG-12's automatic-backup protection. That gives the developers or community enough context to separate a missed manual save, a crash backup, and a restore-boundary issue.

1. Save at base before launch.
2. During map flight, wait for the save icon or confirmation before quitting.
3. Avoid testing save behavior for the first time on a high-value run.
4. After any crash or unexpected reload, check whether an automatic backup preserved a safer point.

## What not to do

Do not download a third-party save fixer, edit save files or move cloud files based only on a forum reply. The current source set supports cautious in-game testing and official bug reporting; it does not verify a save-file format, a safe editor, a restore-folder path or a universal workaround.

Also avoid treating one reload result as a permanent rule. Early Access save behavior can change quickly, and the official posts show that save and crash issues have already been patched. Recheck the live store labels and latest announcements before copying old advice.

1. Do not install unverified save tools.
2. Do not overwrite local or cloud saves while troubleshooting without a separate backup.
3. Do not present a player reply as an official expedition-save rule.
